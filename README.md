## Опыт с данными

### BCH Labs — аналитик данных и руководитель проекта
03.2025 — 09.2026 · удалённо · торговый бот на блокчейне Solana · команда до 5 человек: DevOps, ML-инженер, Rust-разработчики

Данные — поток транзакций и история за месяцы торгов в ClickHouse (кластер с шардированием) и PostgreSQL; Python.

**Хранилище и витрины.** Команде нужна была единая история, на которой воспроизводимо считаются признаки и бэктесты.
- Вела структуру таблиц, загрузку сырых транзакций в таблицы событий и дозагрузку пропущенных периодов (ETL); писала миграции и DDL
- Нашла потерю 6% событий: сравнение количества строк её не показывало, сверка по ключам с исходной таблицей (anti-join) — показала; описала причину в парсере

**Дашборды.** Результаты торговли и состояние рынка нужно было видеть без ручных выгрузок.
- Три дашборда в Grafana, 35 панелей на SQL: анализ торговой сессии (15), симуляция торговли (10), здоровье рынка (10); конфигурация через API
- Заменила пять противоречивых метрик прибыли одной — чистым денежным потоком; медиана вместо среднего, порог по размеру выборки
- После перехода на распределённую базу вернула данные в 28 панелей и проверила по числу строк, что ни одна не теряет данные молча

**Анализ рынка мемкойнов.** Оценить размер рынка и потолок заработка бота для решения о финансировании.
- Данные рынка за год из независимого источника (Dune): 30 тыс. новых токенов, 213 тыс. покупателей и 882 листинга в день (2,9%)
- Пересчитала recall модели на реальный знаменатель — 0,45% вместо 2% — и юнит-экономику бота: доход против расходов команды, точка безубыточности
- Падение рынка в июле 2025 года оказалось уходом пользователей к конкуренту, а метрика 103,5% — ошибкой в числителе

**Классификация пользователей.** Найти кошельки, чьи сделки имеет смысл копировать.
- SQL-пайплайн из 12 шагов: прибыль по токенам, выявление ботов, статистика, классификация, пороговые фильтры, граф переводов
- Нашла ложное срабатывание правила «бот» и вернула в выборку 163 сильных трейдера (+14%); участвовала в обучении моделей LightGBM
- Сверка разметки с внешним API — 0,5% расхождений

**Проверка гипотез.** Команда хотела понять, что на самом деле повышает доходность.
- A/B/C/D-тест параметров исполнения и форвард-тест на 9 торговых сессиях (~780 сделок)
- Нашла ошибку выжившего: +27% по закрытым сделкам против −1,8% по всем покупкам; стоп-лосс, который собирались добавить, на данных ухудшал результат
- Итог: четыре гипотезы роста доходности закрыты количественно — до вложений в разработку

**Управление проектом.** Параллельно вела команду: недельные спринты с целями по результату, бюджет через трекинг часов, найм трёх ролей полным циклом.
